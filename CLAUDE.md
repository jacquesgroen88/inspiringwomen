# CLAUDE.md — Inspiring Women (inspiringwomen.co.za)

## Project Overview

**inspiringwomen.co.za** is a static content website for South African women, covering practical topics: beauty, career, finance, legal rights, health, recipes, lifestyle, and business. It is a fully custom-built static HTML site with a Node.js build system. There is no WordPress, no CMS, no framework — just HTML files generated from a single source-of-truth data file.

**Live URL:** https://inspiringwomen.co.za  
**GitHub repo:** https://github.com/jacquesgroen88/inspiringwomen

## How the Build Works

The entire site is generated by running:

```bash
node build.js
```

Netlify runs this automatically on every deploy (`netlify.toml` → `command = "node build.js"`).

### Data flow

```
articles.js  ──►  build.js  ──►  articles/{category}/{subCategory}/{slug}.html
                      │
                      ├──►  articles/{category}/index.html  (category pages)
                      ├──►  search-data.json               (client-side search index)
                      ├──►  article_inventory.md           (SEO word count audit)
                      └──►  sitemap.xml
```

### Key files

| File | Purpose |
|---|---|
| `articles.js` | **THE source of truth.** Every article lives here as a JS object with `title`, `slug`, `category`, `subCategory`, `author`, `date`, `image`, and `content` (HTML string). |
| `build.js` | Reads `articles.js` and `article_template.html`, generates all article HTML files, category index pages, `search-data.json`, `article_inventory.md`, and `sitemap.xml`. |
| `article_template.html` | HTML template for every article page. Uses `{{PLACEHOLDER}}` tokens replaced by `build.js`. |
| `index.html` | Home page. Also modified by `build.js` to fix nav links and `{{BASE_PATH}}` tokens. |
| `netlify.toml` | Netlify config: build command, publish directory (`.`), security headers. |
| `nav.js` | Mobile burger menu JS (hamburger toggle). Injected into all pages. |
| `search.js` + `search.css` | Client-side search powered by `search-data.json`. |
| `infinite-scroll.js` | Infinite scroll for the article listing pages. |
| `convert-images.js` | Converts `.png` originals to `.webp` using `sharp`. Run manually when adding new images. |
| `generate_pages.js` | Legacy/alternative page generator (not the active build). |
| `inject_articles.js` | Utility script for batch article injection. |
| `run_fixes.js` | Utility for batch HTML fixes. |
| `iw_post_queue.json` | **Pinterest pin queue** (rebuilt 4 Aug 2026) — one pin per live article: `pin_title`, `pin_description`, real `link`, `board`. Regenerate with `build_pin_queue.py`. See the Pinterest Pin Queue section. |
| `article_inventory.md` | Auto-generated SEO audit table (title, category, word count, quality rating). Re-generated on every build. |
| `article_word_counts.md` | Manual word count tracking doc. |
| `iw_records_list.txt` | Record-keeping list of published content. |

## Article Structure

### Adding a new article

1. Open `articles.js`
2. Add a new object to the array:

```js
{
  title: "Your Article Title",
  slug: "your-url-slug",          // used in the URL path
  category: "finance",            // see categories below
  subCategory: "budgeting",       // subfolder name
  author: "Sarah K.",
  date: "May 2026",
  image: "your_image_filename.webp",
  content: `<p>Full HTML content here...</p>`
}
```

3. Add the image to `assets/` (both `.png` and `.webp` versions)
4. Run `node build.js` locally to generate the HTML file
5. Commit and push — Netlify deploys automatically

### URL pattern

```
https://inspiringwomen.co.za/articles/{category}/{subCategory}/{slug}.html
```

## Article Template Tokens

When editing `article_template.html`, these tokens are replaced by `build.js`:

| Token | Replaced with |
|---|---|
| `{{TITLE}}` | Article title |
| `{{META_DESCRIPTION}}` | Auto-generated from first 155 chars of content |
| `{{CANONICAL_URL}}` | Full canonical URL |
| `{{FULL_IMAGE_URL}}` | Full URL to the article's featured image |
| `{{STRUCTURED_DATA}}` | JSON-LD Article schema block |
| `{{CATEGORY}}` | Category name (uppercased) |
| `{{AUTHOR}}` | Author name |
| `{{DATE}}` | Article date |
| `{{IMAGE}}` | Relative path to the featured image |
| `{{BASE_PATH}}` | Relative path prefix (e.g. `../../../` from article pages, `` from root) |
| `{{CONTENT}}` | Full HTML article body |
| `{{RELATED_ARTICLES}}` | Auto-generated related articles grid (6 articles, same category first) |

## Performance Optimisations Applied

These were done explicitly to improve PageSpeed / Core Web Vitals:

1. **WebP images** — All 88+ images converted from PNG to WebP (saved ~53MB)
2. **Images resized to 800px** — Prevents oversized images killing LCP
3. **Inline styles.css** — Styles are inlined in `article_template.html` (no render-blocking CSS request)
4. **Async font loading** — Google Fonts loaded with `media="print"` swap trick
5. **Preconnect hints** — `fonts.googleapis.com`, `fonts.gstatic.com`, `cdnjs.cloudflare.com`
6. **Deferred search.css** — Non-critical CSS deferred
7. **Lazy loading images** — `loading="lazy"` on article card images
8. **Infinite scroll** — Article feeds load progressively (extracted to `infinite-scroll.js`)

## Pinterest Pin Queue

**Rebuilt 2026-08-04. The channel is Pinterest, not Instagram.** Instagram posts carry no links, so an IG-shaped queue cannot serve a website-traffic goal. Pinterest also ignores domain authority, which is this site's core weakness (22 backlinks, all pointing at the homepage).

`iw_post_queue.json` holds one pin per LIVE article (95 as of 4 Aug):
- `order` — running order, proven clusters first: beauty (11), then finance (10), then lifestyle, career, health, recipes, business, community, legal
- `pin_title` — capped at 100 characters
- `pin_description` — keyword-led complete sentences, because Pinterest is a search engine and not a feed
- `link` — real destination URL (Pinterest has a link field, so never write "link in bio")
- `image_url`, `board`, `posted`, `posted_at`

**Regenerate with** `build_pin_queue.py` (lives in Mission Control at `JCE Media/clients/InspiringWomen-tools/`). It reads `articles.js`, skips staged articles, excludes headings and medical disclaimers from descriptions, and strips em dashes.

**Known gaps:** no Pinterest account exists yet, and the images in `assets/` are 1024x1024 squares (JPEGs with `.png` extensions) where Pinterest wants 2:3 / 1000x1500.

**Note:** Twitter/X was removed from the site's social links.

## Deployment Checklist

When making changes:

1. Edit content in `articles.js` (or template/styles in `article_template.html`)
2. Run `node build.js` locally to regenerate HTML files
3. Verify output in browser
4. `git add` the changed files (be careful not to commit `node_modules/`)
5. Commit and push to `main`
6. Netlify auto-deploys in ~1–2 minutes

**Never** manually edit files in `articles/{category}/{subCategory}/` — they are overwritten on every build. Always edit `articles.js` instead.
